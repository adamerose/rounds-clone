Arena data

Write arenas as RON files under assets/arenas/. Use all-kinds.ron as an example of every supported object kind.

Coordinates and bounds

World units are pixels, Y points up, and rotations are radians. Each file names a frame as (left, bottom, right, top).

The camera shows that frame. The loader rejects geometry, motion endpoints, fixed anchors or spawns outside it, including non-finite values.

The frame keeps its aspect ratio, with letterboxing when needed. Data arenas have no lens distortion or chromatic offset.

Provide one to four spawn coordinates. The current two-fighter adapter uses the first two; a single slot is reused for both fighters.

Pieces

Each object has a unique id, position, shape, kind and RGB colour. Rotation defaults to zero and mass defaults to one.

Shapes are Rectangle(size: (width, height)), Circle(radius: r) or Polygon(vertices: [...]).

Polygon vertices are local to the object and must form a strictly convex contour. Rectangles and circles require positive finite dimensions.

Solid pieces hold their position. Loose pieces have explicit collider mass and fighters and shots push them.

Breakable(loose: false) holds its position until its health reaches zero. Set loose: true for a movable breakable piece.

Breakable pieces require health: Some(n). Shots remove 25 health. A destroyed piece and its attached chains disappear together.

Background pieces are drawn behind fighters and have no collider. Fighters and shots pass through them.

Saw(loose: false, teeth: 8, angular_velocity: 3.0) requires a circle; loose: true lets it fall and be pushed.

A saw contact removes 35 health. A fast dynamic piece removes health according to its relative impact speed and mass, once per contact entry.

Solid pieces use filled shapes, loose pieces have pale outlines, breakables have cracks, backgrounds are dark, chains have links, and saws have teeth.

Motion and chains

Motion is Some((path: [(0.0, 0.0), (120.0, 0.0)], period_seconds: 2.0, angular_velocity: 0.0)).

Path points are offsets from the initial position. Segments take equal time and the last point connects to the first; an empty path rotates in place.

Moving pieces are kinematic so they push fighters. Position derives from the arena age; repeated loops do not accumulate translation error.

Chains name body_b, an optional body_a, a world anchor, a positive maximum length, and a unique chain ID.

When body_a: None, the anchor is fixed. Otherwise the chain joins the centres of the named pieces and ignores the world anchor.

Chains never break from shots or force. Breaking either endpoint removes that chain and frees the surviving piece.

Loading and previewing

ArenaDefinition::load validates one file; load_arena_directory loads every RON file in filename order.

AuthoritativeMatch::from_arena_file runs a session from a file and checks it at tick boundaries for validated edits.

File checks occur every fifteen ticks, giving at most 250 ms of reload delay in live play without reading the filesystem on every physics tick.

A valid edit resets geometry, spawns and transient combat state. Invalid edits leave the running arena intact; inspect arena_reload_error().

Reloads preserve network ticks, match phase, scores and loadouts. Invalid later-stage edits use the last validated geometry and report the error.

Set QUARREL_ARENA_DIR to override the asset directory. Otherwise assets are located beside an enclosing working or executable directory.

cargo run --locked -p quarrel-client -- arena-preview --arena assets/arenas/all-kinds.ron --output out/arena-preview.png

This uses Bevy's offscreen renderer without opening a window. Previews belong under ignored out/, not in Git.

The converted replay files retain compatibility surfaces and body definitions. New arenas use objects and chains; the profiles remain until ticket 78.
