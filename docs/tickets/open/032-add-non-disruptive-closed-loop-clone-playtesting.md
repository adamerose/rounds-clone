# Add non-disruptive closed-loop clone playtesting

The clone can replay predetermined inputs and render selected states, but an agent cannot yet observe the running game, choose legal actions from those observations, and continue playing without controlling the user's desktop. Add a debug-only closed-loop playtest surface so visual and behavioral mismatches can be explored during development without moving the physical pointer, injecting global keyboard input, activating a foreground window, or exposing an invented player-facing bot mode.

## Outcome

- A distinct `--debug-agent-playtest <absolute-output-root>` startup mode accepts versioned legal semantic actions for both players, advances the real deterministic match shell, and returns one ordered observation after each accepted action interval without using operating-system mouse, keyboard, controller, focus, or window-activation APIs.
- Human-style decision observations contain only a monotonically increasing sequence number and the renderer-owned frame a person would see. Seed, exact tick, accepted interval, per-tick match hashes, and protocol diagnostics are written by a separate trace recorder and are not present in the driver callback or decision-response type; a separately named structural mode may expose them only with a `non-human-structural` trace label and cannot satisfy perceptual evidence.
- Starting from `Match.Create(1UL)`, a local deterministic adaptive driver controls both players through the two opening picks and first full round, then stops successfully only when `FaithfulSubsetMatchShell.IsAtIncompleteFidelityBoundary` becomes true at the first loser-draft boundary and the complete incomplete-fidelity message is rendered. Reaching `MatchResult`, exhausting a bound, EOF, or quitting earlier is failure.
- At least one bounded renderer-backed run uses multiple returned frames to choose subsequent legal actions and reaches that exact terminal boundary. An explicit renderer-unavailable result is valid for headless protocol tests but cannot close the ticket or satisfy human-style playtest evidence.
- The completed debug trace replays the same accepted interval actions into a fresh shell and reproduces every stored `Match.Hash` value and the same terminal boundary. It is debug evidence only, not a new protected replay, golden fixture, or complete-match replay format.
- The route enforces the exact resource, artifact, timeout, and cleanup limits below, exits automatically, refuses evidence overwrite, and leaves no attributable process. It remains internal verification infrastructure and is unreachable from ordinary play, release routing, the existing incomplete-fidelity capture route, and protected replay routing.

## Decisions

- The protocol identifier is `rounds-agent-playtest-v1`. After an initial sequence-0 observation, the driver submits exactly one UTF-8 JSON request and waits for exactly one response; pipelined, duplicate, skipped, negative, or out-of-order sequence numbers fail before advancing simulation.
- Each request is `{protocol, sequence, intervalTicks, players}`. `intervalTicks` is an integer from 1 through 30. `players` has exactly two entries, each containing `move` in `-1|0|1`, Boolean `jump`, `fire`, and `block`, plus finite `aimX` and `aimY` in `[-1,1]`; unknown or missing fields, non-finite numbers, or extra/missing players fail closed.
- Transport is newline-delimited UTF-8 JSON: requests use standard input and protocol responses use standard output. The launcher uses Godot's quiet mode, all diagnostics and engine logging go to standard error, each protocol object occupies exactly one LF-terminated line, and no other standard-output record is permitted.
- Initial sequence 0 and every accepted request produce exactly one frame response: `{protocol:"rounds-agent-playtest-v1",sequence:N,status:"frame",framePath:<absolute finalized PNG>,frameSha256:<lowercase 64-hex>,width:W,height:H,terminal:B}` with no additional fields. The route writes and closes `frame-NNNN.png.partial`, verifies dimensions and SHA-256, atomically renames it without overwrite to `frame-NNNN.png`, and only then publishes the response; `terminal` is true only for the rendered first-loser-draft incomplete-fidelity boundary.
- Any failure produces exactly one response with no frame fields: `{protocol:"rounds-agent-playtest-v1",sequence:N-or-null,status:"error",stage:S,code:C}`. Allowed stage/code pairs are `request-parse/malformed-json`, `request-validate/invalid-schema`, `sequence/invalid-sequence`, `simulation/simulation-failed`, `renderer/renderer-unavailable`, `frame/frame-publish-failed`, `resource/resource-limit-exceeded`, `lifecycle/timeout`, `terminal/invalid-terminal`, and `replay/replay-mismatch`; the process then exits nonzero after cleanup. `sequence` echoes a valid parsed integer and is null otherwise. An invalid request never advances or produces a frame.
- Each action is held unchanged for every 60 Hz tick in its interval. Draft movement, draft confirmation, jump, and block preserve the simulation's existing edge semantics: a new edge requires at least one intervening tick with the relevant move axis at zero or held Boolean false. A zero aim vector preserves the current aim; any nonzero finite vector follows the existing normalization path. Simultaneous legal controls remain legal.
- The owner verifies the finalized response path is the exact expected file beneath its task-owned root, rechecks its declared hash and dimensions, decodes it completely, and passes the local adaptive driver an immutable `HumanPlaytestObservation(sequence, pixelBytes, width, height)` value only. `pixelBytes` is an immutable copied buffer of tightly packed rows in top-to-bottom order, four bytes per pixel in red-green-blue-alpha order, eight bits per channel, sRGB color bytes, and straight unpremultiplied alpha, with no padding (`pixelBytes.Length == width * height * 4`) or mutable decoder backing exposed. It never passes the path, hash, terminal flag, trace writer, or structural observation into that callback. Trace-envelope metadata is passed directly from the owner to a separate recorder; direct type/API tests prove the adaptive driver cannot read it. Structural mode uses a distinct request flag and `non-human-structural` label and is excluded from renderer-backed acceptance.
- Model reasoning, when used later, is an external low-frequency supervisor over this protocol. This ticket adds no SDK, outbound request, API key, account, spend, model selection, or nondeterministic dependency; admission evidence uses a local deterministic adaptive driver and a counterfactual test in which a different visible observation with identical prior history causes a different legal next action.
- The route owns at most 120 action requests, 3,600 simulation ticks, 121 rendered frames including sequence 0, 90 seconds wall time, two players, and the integrated `CombatTuning.LiveBulletCap` of 2,048 live bullets. Crossing any limit fails and triggers owner cleanup.
- Renderer-backed output is at most 1280 by 720 and one frame per observation, with no more than 10 observations emitted per wall-clock second. The complete task-owned process tree contains only the driver/owner and game, runs below normal priority on at most two logical processors, stays below two GiB private memory and two GiB attributable dedicated GPU memory, and rejects a run that exceeds 70 percent total GPU-engine utilization.
- Before a renderer-backed run, collect ticket 031's independent 10-second, 20-millisecond scheduling-heartbeat baseline. During the run, the 95th-percentile delay must be no more than 5 milliseconds above baseline and no more than 15 milliseconds absolute, with no delay above 50 milliseconds; otherwise kill the exact task-owned process tree and reject the evidence. No renderer-backed or GPU proof runs while the user is active unless these gates and automatic cleanup are already in force; pure simulation/protocol tests may proceed.
- Use only the standard-input/standard-output NDJSON boundary defined above; do not open a local pipe or network listener, install a virtual input driver, enable a Windows feature, create an account, or change host security configuration. The owner applies a 95-second hard timeout and exact process-tree cleanup in addition to the in-route 90-second limit.
- The absolute output root must not already exist and must be created exclusively. It contains at most `frame-0000.png` through `frame-0120.png`, each created without overwrite, plus `trace.jsonl.partial` while running; successful replay verification atomically renames that trace to `trace.jsonl` and atomically publishes `manifest.json` with protocol/build identity, dimensions, frame hashes, accepted actions, tick/hash coverage, limits, samples, terminal boundary, and completion marker. Total output is capped at 256 MiB.
- Malformed input, timeout, crash, resource violation, renderer error, or incomplete replay verification produces no final manifest: the owner kills only the exact task-owned process tree, removes the exact task-owned output root including partial frames/trace, emits one stage-specific error marker, and proves both path and process absence. Raw frames remain external and untracked; committed evidence contains only hashes, dimensions, tick identities, semantic traces when clean-room-safe, resource samples, and independently derived findings.
- This ticket does not claim fidelity to installed ROUNDS, replace ticket 031's target-build capture, or deliver ticket 022's complete-match replay and 10,000-match self-play. It supplies the smaller clone-side interaction surface those later comparisons can use.
- `StartupMode.DebugAgentPlaytest` is mutually exclusive with ordinary match, replay, and the existing incomplete-fidelity evidence mode; parsing requires a debug build and a valid absent absolute output root before any protocol/file creation. Its owner disables `_PhysicsProcess` and advances only supplied `PlayerInput` values; ordinary match `_PhysicsProcess` remains the only route that reads `Godot.Input` or mouse position, and tests prove the playtest route never enters it.
- No visible verification window is allowed while the user is active. The required renderer-backed proof must be deferred if it cannot remain non-activating and wholly on monitor 4 without weakening any input, placement, or host-impact gate.

## Evidence required

- Focused protocol tests prove the exact NDJSON request/frame/error schemas and framing, atomic final-frame-before-response ordering, canonical immutable top-to-bottom tightly packed straight-alpha sRGB RGBA8 callback bytes and length, standard-error diagnostic separation, one-request/one-response sequence, held and rising-edge semantics, legal simultaneous controls, 1–30-tick intervals, 120-request/3,600-tick/2,048-bullet bounds, trace hashes, fresh-shell replay, terminal boundary, every allowed error pair, malformed/duplicate/out-of-order rejection, timeout, artifact lifecycle, and exact cleanup.
- Negative route tests prove ordinary, release, existing incomplete-fidelity evidence, and protected replay routes cannot enable the playtest surface; invalid/existing/relative output roots create nothing; missing priority/affinity/resource/heartbeat limits, OS-level input fallback, and renderer unavailability fail explicitly. Direct code checks keep `Godot.Input` and global mouse reads exclusively in ordinary match processing.
- Two independent runs of the same accepted action trace produce identical actions, every per-tick `Match.Hash`, phase transitions, incomplete-fidelity terminal boundary, trace/manifest bytes apart from explicitly listed timing/resource samples, and renderer-frame hashes under the same rendering configuration.
- A bounded renderer-backed run wholly on monitor 4 supplies at least five distinct frames, including sequence 0, active duel play, and the terminal incomplete-fidelity frame, to the local adaptive driver's human-only callback. A counterfactual visible frame produces a different legal action, and the report separates visual findings, behavioral findings, resource/heartbeat evidence, unavailable diagnostics, and exact cleanup.
- Process telemetry proves the CPU-affinity, priority, process-count, memory, GPU, cadence, resolution, output-size, and responsiveness bounds throughout the renderer-backed run. The exact target window is non-activating with its center on monitor 4 before every captured frame; no window, input, or unrelated pixels from monitors 1 through 3 are observed.
- Zero-warning build, focused and full simulation/replay suites, repository checks, ticket checker, and `git diff --check` pass. Existing golden replay bytes, ordinary-play behavior, dependencies, and shipped UI remain unchanged.
