# Add a deterministic base-projectile evidence route and isolated launcher

Ticket 034's source correction cannot be visually approved without rendering an exact-candidate projectile, but reaching that transient state through interactive play would require operating-system input and could disrupt the user.
The deterministic route now exists, but a normal Godot launch could still activate on the user's interactive desktop, start before resource controls are applied, publish into an ambiguously owned path, or render stale assemblies.
Complete the route and add a bounded Windows launcher that can later render the exact candidate on a private desktop without ever switching that desktop into the input path.

## Outcome

- A debug-only command-line route constructs an active `arena-006` world through the real simulation API and vanilla player/combat profiles; the frozen state contains exactly one ordinary owner-0 projectile in flight, with no cards or custom combat profile involved.
- The route draws one frame, publishes `frame-0000.png` beneath one atomically acquired, absent absolute output root, emits one exact projectile-specific attestation, and exits automatically.
- A Windows-only launcher has a side-effect-free plan mode and one explicitly separate execute mode. Execute mode creates a private desktop, never calls `SwitchDesktop`, and starts the pinned Godot process there suspended and contained in a kill-on-close job before it can run.
- The launcher fails closed unless the preflight topology identifies `\\.\DISPLAY4` at Godot screen index 3 with physical bounds `(364,-1080) 1920x1080`, the intended 1280x720 window lies wholly within those bounds, and the process attests the same private desktop, screen, position, and size.
- A successful run is attributable to one clean candidate commit, one immediately preceding bounded build, one exact runtime assembly hash/MVID, one exact pinned Godot executable, one owned output root, one validated PNG, and one child process tree that has fully terminated.
- Ordinary play, replay, the incomplete-fidelity boundary capture, and agent playtesting retain their existing routing and behavior.
- The route never reads global input and never enters continuous physics.

## Decisions

- Reuse `DebugEvidenceCaptureProtocol` and the existing viewport/monitor attestation lifecycle rather than adding another capture implementation.
- Give projectile evidence its own exact completion/error marker namespace; preserve every byte of the existing incomplete-fidelity evidence markers.
- Reach the projectile through `World.CreateMatch` and `Sim.Step`, using embedded `arena-006`, `PlayerTuning.Vanilla`, `CombatTuning.Vanilla`, and two `PlayerCombatProfile.Vanilla` instances.
- Fire upward from player 0 on the first active tick so the projectile is visible, remains clear of the arena geometry, and is produced by ordinary fire mechanics.
- Replace the projectile route's bare PNG destination with the existing reparse-safe `AgentPlaytestArtifactOwner` absent-root acquisition and finalized-frame verification. Add the narrow Godot PNG decoder adapter needed to publish one RGBA8 frame and a `CompleteVerifiedSingleFrame` transition that succeeds only after exactly terminal sequence 0 has been published and reverified, marks the owner complete without a manifest, and rejects missing, nonterminal, repeated, or extra frames. Do not otherwise weaken or fork the ownership rules.
- Set per-monitor-v2 DPI awareness before topology enumeration. Identify the monitor by the exact Win32 device name `\\.\DISPLAY4`, use physical-pixel bounds throughout, require its enumerated ordinal to be 3, and pass both canonical `--screen 3` and `--position 684,-900` pre-start arguments. Any topology, DPI, ordinal, or containment mismatch is a refusal, not a fallback.
- The executable is the repository's bootstrap-pinned Godot 4.7.1 .NET console binary at `.tools/godot-4.7.1/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64_console.exe`, version `4.7.1.stable.mono.official`, SHA-256 `b2c334ff6bf1e07ded41b80bd6f4785485650db6ddbb2740b802930f35237c26`. Resolve this exact path beneath the candidate repository and refuse any reparse point, version, or hash mismatch.
- Build the exact clean candidate commit immediately before execute mode with `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\MSBuild.exe game\Rounds.Game.csproj /noAutoResponse /t:Rebuild /p:Configuration=Debug /p:Restore=false /p:UseSharedCompilation=false /p:BuildProjectReferences=true /m:1 /nr:false /v:minimal /warnaserror`. `/noAutoResponse` must disable both executable-adjacent `MSBuild.rsp` and upward-searched `Directory.Build.rsp`. Require file version `17.14.40.60911`, product version `17.14.40+3e744208875e56e4bf0bc22c40a1c431fb150987`, and executable SHA-256 `0f7daba445ba37b652ae4180270ab3eff27acbbe5d411d3b05dad51aab16404c`. Use an explicit non-inherited sanitized environment containing only reviewed OS necessities plus pinned build entries; require exact effective values and prohibit ambient MSBuild, NuGet, SDK, restore, and DOTNET injection. Set `DOTNET_PROCESSOR_COUNT=2`, `MSBUILDDISABLENODEREUSE=1`, `MSBuildEnableWorkloadResolver=false`, and `MSBuildSDKsPath=<repository>/.tools/dotnet/sdk/8.0.423/Sdks`; require the exact SDK version and bytes from `global.json` with roll-forward disabled, exact reference pack 8.0.29, identity-bound project/lock/assets inputs for Game/Replay/Sim, and exact identity-bound Godot package cache content. Refuse missing or mismatched locked inputs without restore or network. The direct child starts suspended, matches the retained opened MSBuild identity before resume, runs in a separate kill-on-close job at affinity `0x3`, below-normal priority, one-process and admitted memory limits, drains bounded stdout/stderr concurrently, and must prove zero exit, zero warnings, and empty job by the deadline. `Rebuild` must prove the prior runtime path absent before spawn, recreate and retain no-write/no-delete identity leases for `Rounds.Game.dll`, `Rounds.Replay.dll`, and `Rounds.Sim.dll`, hash/read exact stable PE/MVID/assembly-name data only through those handles, and retain their reparse-free ancestor chains through preflight, Godot load, child attestation, zero exit, and empty-job proof. The child computes and attests its own Game assembly hash/MVID and the launcher requires equality.
- Use direct `CreateProcessW` with an argv-to-command-line encoder tested against Windows parsing, `CREATE_SUSPENDED | CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP | BELOW_NORMAL_PRIORITY_CLASS | EXTENDED_STARTUPINFO_PRESENT | CREATE_UNICODE_ENVIRONMENT`, an explicit Unicode environment block, and `STARTUPINFOEXW.lpDesktop` naming a newly created nonce-scoped private desktop. Its `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` contains exactly four inheritable child handles: a read-only `NUL` standard input, the stdout pipe write end, the stderr pipe write end, and the acknowledgement pipe read end; every parent-side handle and every other launcher handle is non-inheritable. Do not use a shell, `Process.Start`, a script-spawned child, or an untested string command API.
- Before `ResumeThread`, create a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, a single-active-process limit, below-normal priority, a two-CPU affinity mask (`0x3`), a 768 MiB per-process commit limit, and a 1 GiB job-wide commit limit; assign the suspended process and retain desktop, job, process, and primary-thread handles until verified termination. Enforce a 30-second deadline from `ResumeThread`, an 8 KiB stdout cap, and a 64 KiB stderr cap. A timeout, cap breach, parse failure, unexpected child, or disposal kills the job. Cooperative child failures clean through their retained artifact leases; forced termination preserves and reports the exact residue path because killing the child destroys the only reparse-safe ownership proof. The launcher must never reopen and recursively delete that unproven path.
- Create and own the private desktop from one dedicated native-boundary worker thread so any desktop association made by `CreateDesktopW` cannot alter the launcher's main/test thread. Never call `SwitchDesktop`, `SetThreadDesktop`, `SetForegroundWindow`, `ShowWindow`, input APIs, or controller APIs. Preflight and postflight require the input-desktop identity to remain the same; a foreground-event observer requires that no foreground window during the run belongs to the child job, while allowing the user to change focus among their own applications. The child must attest the private desktop, which is closed only after the job is empty.
- Canonical argv order is `--quiet --path <exact-repository-game-directory> --screen 3 --position 684,-900 --resolution 1280x720 --windowed --audio-driver Dummy --rendering-method gl_compatibility -- --debug-base-projectile-evidence <exact-owned-absent-output-root>`. Quiet mode suppresses Godot logging; the launcher rejects additional engine, project, or user arguments.
- The projectile route writes exactly one newline-terminated completion marker directly to `Console.Out` and flushes it; it writes projectile error markers and all diagnostics directly to bounded `Console.Error`. It does not use `GD.Print`/`GD.PushError`, so `--quiet` cannot suppress its protocol. Preserve the existing incomplete-fidelity route's marker bytes and stream behavior. The literal stdout grammar and field order are `DEBUG_BASE_PROJECTILE_EVIDENCE_COMPLETE stateHash=6a25f798f6582a29 bulletId=0 ownerId=0 desktop=RoundsEvidence-<nonce> screen=3 windowX=684 windowY=-900 windowWidth=1280 windowHeight=720 viewportWidth=1920 viewportHeight=1080 assemblySha256=<assembly-sha> assemblyMvid=<assembly-mvid> pngSha256=<png-sha> frame=frame-0000.png`, where `<nonce>` is exactly 32 lowercase hexadecimal characters generated by the launcher, both SHA values are exactly 64 lowercase hexadecimal characters, and `<assembly-mvid>` is exactly 32 lowercase hexadecimal characters (`Guid` format `N`). No whitespace, sign, prefix, alternate case, field reorder, duplicate key, additional key, relative-name variant, or second non-empty stdout line is accepted.
- The launcher creates a dedicated anonymous acknowledgement pipe before `CreateProcessW` and passes only its inheritable read handle in the explicit environment as `ROUNDS_EVIDENCE_ACK_HANDLE=<unsigned-decimal-handle>`. After publishing and reverifying the terminal frame, the child emits the completion marker but retains its root/file identity leases and waits at most five seconds for exactly one `0x06` byte or pipe closure. While those leases prevent root/file replacement, the launcher opens identity-bound read handles, validates the exact root contents/hash/decode, and writes `0x06` only on success. The child then calls `CompleteVerifiedSingleFrame`, disposes the leases, and exits zero. Timeout, EOF, any other byte, or validation failure produces nonzero exit and child-owned cleanup; the launcher cannot report success until the acknowledgement, zero exit, and empty job all occur.
- The requested output root must be an absent, normalized absolute child of an existing non-reparse parent outside both the canonical candidate repository and the operating-system temporary directory; compare resolved parent handles/identities, not only path strings. The child retains the root/file identity leases through terminal publication. Success leaves only `frame-0000.png`; failure cleanup is limited to the child's still-retained proof as described above.
- Success requires zero exit, an empty job, unchanged input-desktop identity, no foreground event attributable to the job, exact marker fields, an owned `frame-0000.png` whose SHA-256 matches, complete RGBA8 decode at exactly 1920x1080, no partial or extra files, and no process or output-root handle leak. Preserve the finalized PNG on success; delete only the exact owned root on failure.
- Plan mode accepts injected topology, filesystem metadata, candidate/build identity, foreground/desktop identity, and output-root facts, emits the immutable launch plan or a refusal, and never creates a process, desktop, directory, or file. Unit tests exercise plan mode and native-boundary orchestration with fakes; they must not launch Godot or any GUI.
- Keep this ticket infrastructure-only: it enables later visual verification but does not itself prove the projectile matches installed ROUNDS. The ticket stays open until an attended execute-mode run at the exact reviewed candidate produces approved monitor-4 pixels.
- Do all implementation and verification headlessly with at most two logical processors; do not invoke execute mode, Godot, a renderer, a browser, a window, or any input mechanism while the user is playing.
